# NEO — 네이버 검색과 AI 브리핑 대응

한국 시장 서비스라면 검색 유입의 상당 부분이 네이버다. 그런데 글로벌 SEO·GEO 가이드는
네이버를 다루지 않는다. 목표 두 개: ① 네이버 검색 노출 ② **AI 브리핑 인용**.

## 1. 서치어드바이저 — 여기부터 깔고 간다

- [ ] searchadvisor.naver.com 사이트 등록 + 소유 확인 (사용자 계정 필요 — 절차 안내만)
- [ ] 사이트맵 제출, robots.txt에서 **Yeti(네이버 크롤러) 허용** 확인
- [ ] **웹마스터도구를 주간 리듬으로 읽어라**: 콘텐츠 노출/클릭 추이 + 검색어별 클릭·CTR·순위.
      어떤 질문이 유입을 만드는지가 여기서 보인다
- [ ] 새로 만든 중요 페이지는 사이트맵만 믿지 말고 웹페이지 수집 요청을 직접 넣어 반영을 앞당긴다

## 2. AI 브리핑 인용 따내기

네이버 AI 브리핑은 **문단 단위로 출처 칩**을 단다. 인용되는 페이지의 조건:

- [ ] **구조화된 사실**: 항목-값 그리드(요금/기간/조건…)처럼 기계가 읽기 좋은 구성.
      산문 덩어리보다 **라벨-값 구조**가 인용된다
- [ ] **1차 소스 신호**: 공식 출처 기반임을 페이지가 명시 + 원문 링크 병기
- [ ] **신선도**: 사건 발생 후 빠르게 페이지가 서는 쪽이 인용을 가져간다
- [ ] **모바일 최적화**: 네이버는 모바일 우선이다. 모바일 첫 화면에 핵심이 보여야 한다
- [ ] 검증: 대상 키워드를 **네이버 앱에서** 검색해 출처 칩을 실제 확인·기록

## 3. 블로그와 자사 도메인, 두 갈래로 간다 (inside / outside)

네이버는 자기 생태계 안(inside) 콘텐츠를 우대하고, 정확한 데이터는 자기 도메인(outside)에
있어야 한다. **정답은 투트랙이다.**

- **inside** — 브랜드 블로그: 네이버 안에서 신뢰·체류를 쌓는다. 검색 상위와 스마트블록에
  잡히는 건 블로그 글인 경우가 많다
- **outside** — 자기 도메인: 팩트의 원장. AI 브리핑이 인용하는 건 결국 구조화된 데이터 페이지다
- 블로그에서 자기 도메인 데이터 페이지로 자연스럽게 연결하되 **링크 도배는 금지**

### 왜 투트랙인가 — 채널마다 닿는 엔진이 다르다

네이버 블로그는 역사적으로 외부 크롤러를 막아온 폐쇄 플랫폼이라, 글로벌 생성형
엔진(ChatGPT·Gemini·Claude 계열)의 인용 실측에서 **거의 잡히지 않는 것으로 반복
관측된다.** 반면 티스토리 등 오픈웹 블로그는 이 엔진들에 도달한다. 한국은 언론
기사보다 **블로그·위키·커뮤니티가 AI 인용의 중심**이라는 관측도 여러 실측에서
공통적이다 — 글로벌 PR 중심 전략을 그대로 이식하면 한국에서는 잘 작동하지 않는다.

⚠️ 위 관측은 카테고리·시점에 따라 다르다. **우리 업종의 질의로 직접 재서 확인하라**
(`measure.md` 2번) — 남의 실측은 방향 가설이지 우리 수치가 아니다.

> **어느 엔진의 답이 되고 싶은지를 먼저 정하고, 채널은 그 다음에 고른다.**
> 채널을 고르는 순간 도달할 수 있는 엔진의 범위가 함께 정해진다.

- 네이버 검색·AI 브리핑이 목표 → 네이버 블로그(inside)
- ChatGPT·Gemini가 목표 → **오픈웹 채널이 필수다.** 네이버 안에만 쌓으면 그 엔진들에는 없다
- ⚠️ 통제 불가한 위키류(나무위키 등)는 한국에서 인용 비중이 높다 —
  사실관계·최신성을 **상시 모니터링 대상**에 올려라 (`reputation.md` 3번)

## 4. 지역·오프라인 사업이면 추가

- [ ] 네이버 플레이스 등록·정보 정확성 (영업시간·전화·주소가 웹사이트와 **일치**해야 한다.
      불일치는 엔티티 분열이다 — `llmo.md` 1번과 같은 문제)
- [ ] 지점이 여럿이면 지점별 페이지 + LocalBusiness JSON-LD
- [ ] "지역명 + 서비스" 검색 질문에 대응하는 전용 랜딩

## 5. 하지 말 것 (네이버는 특히 민감하다)

- ❌ **서로이웃·댓글 품앗이 자동화** — 스팸 필터의 대표 감지 대상. 걸리면 블로그 저품질로
      이어진다. 네이버가 최대 유입 채널이라면 **그 채널을 걸고 하는 도박**이다
- ❌ 같은 문장을 복사해 댓글·포스팅에 대량으로 뿌리는 것 — 반복 패턴 자체가 스팸 판정 근거다
- ❌ 올렸다 고치고 지우기를 반복하는 운영 — 그때마다 문서 신뢰 점수가 깎인다

## 6. 측정

- 웹마스터도구 노출/클릭을 주 1회 스냅샷 (공개 API가 없으니 수동 또는 자체 수집)
- AI 브리핑 인용은 **앱에서 직접 검색**으로만 확인된다 (로그로 안 잡힌다)
- 주말 하락 패턴 확인: 평일성 주제는 주말에 노출이 꺼지는 게 정상이다 — 실수요의 증거
## 7. 다음·카카오는 이 문서가 아니다

다음은 네이버와 **크롤러 토큰도, 소유확인 방식도, 등록 절차도, AI 요약을 만드는 모델도**
다르다. 한 레인에 묶어두면 둘 다 안 보여서 **KEO 레인으로 분리**했다 — `lanes/daum.md`.

판단 근거는 [결정 기록](../docs/decisions/2026-09-11-keo-lane.ko.md)에 남겼다 — 묶여 있는 동안 무엇이 샜는지, 어떤 대안을 왜 기각했는지.

묶여 있던 시절의 실수 두 가지를 남겨 둔다:

- robots.txt에 `Daumoa`만 적고 `DAUM`을 빠뜨렸다. robots는 **가장 구체적인 UA 그룹 하나만**
  적용하므로 `DAUM`으로 오는 요청은 `*` 그룹으로 떨어진다
- 다음 소유확인을 네이버처럼 메타 태그로 찾으려 했다. 다음은 **URL + PIN** 방식이라
  크롤로는 등록 여부를 증명할 수 없다 — 사람 확인 항목이다
