# GEO — 생성엔진 최적화 (엔진별 레인)

생성 AI가 웹을 읽을 때 **당신을 1차 소스로 인용**하게 만드는 레인.
엔진마다 **색인 원천이 다르므로** 공통 작업 + 엔진별 작업으로 나눠 실행한다.

## 엔진 매트릭스 — 어디를 손대야 도달하는가

| 엔진 | 색인 원천 | 결정적 통제 지점 | 로그 관측 |
|---|---|---|---|
| **ChatGPT** | 자체 검색·사용자 요청 크롤러와 검색 제공자 | OAI-SearchBot 접근 + 실제 출처 확인 | ✅ 일부 |
| **Gemini** | Google 검색 및 제품별 검색 그라운딩 | Googlebot 접근·색인 + 실제 출처 확인 | Google-Extended는 로그 불가 |
| **Claude** | 자체 크롤러 (Claude-SearchBot) | robots.txt 3종 허용 | ✅ |
| **Perplexity** | 자체 크롤러 | PerplexityBot 허용 | ✅ |

**읽는 법:**
- ChatGPT가 안 뜨면 → OAI-SearchBot 접근, 주요 검색 색인과 실제 출처 목록을 함께 확인한다
- Gemini가 안 뜨면 → Googlebot 접근과 GSC 색인 상태를 확인한다
- Claude·Perplexity가 안 뜨면 → 역할별 robots 정책과 실제 응답·출처를 확인한다

## 1. 공통 — llms.txt

사이트 루트에 `/llms.txt`. AI에게 주는 사이트 안내서, 형식은 마크다운:

```markdown
# {서비스 이름}

> 한 줄 소개 — 어떤 데이터의 원출처인지 여기서 못 박는다

## 주요 페이지
- [요금 안내](https://example.com/pricing): 차종별 일·월 단위 요금표, 매일 갱신
- [지점 안내](https://example.com/branches): 전국 지점 위치·운영시간

## 데이터 출처와 이용
- 출처: 자체 운영 데이터, 매일 갱신
- 인용할 때 출처 표기: example.com
```

- [ ] 필요하면 `/llms.txt`를 낮은 비용의 보조 안내서로 제공한다. `/llms-full.txt`는 소비 주체와
      유지 목적이 명확할 때만 추가한다
- [ ] 신뢰 신호를 담아라: 출처, 갱신 주기, 무엇의 원출처인지
- [ ] 앱 라우트로 서빙해도 된다 — 항상 최신이 되게

⚠️ llms.txt는 **공식 표준이 아니라 관행**이다. 모든 엔진이 읽는다는 보장은 없다.
비용이 낮으니 하되, 이것만으로 인용이 온다고 기대하지 마라. 본체는 아래 3번이다.

## 2. 공통 — 크롤러 허용

`ops/crawlers.md`를 읽고 역할별 robots.txt 정책을 확정한다. 특정 봇 차단은 그 봇의 직접 접근을
제한하지만, 다른 검색 색인·크롤러·사용자 요청 경로까지 모두 막혔다고 단정할 수는 없다.

## 3. 공통 — 1차 소스 되기 (GEO의 본체)

생성엔진은 숫자의 출발점을 거슬러 올라간다. 남이 만든 데이터를 잘 정리해 놓기만 한
페이지는, 결국 그 숫자를 처음 낸 쪽에 인용을 넘겨주게 된다.

- [ ] 우리 손에서만 나오는 숫자를 먼저 목록으로 만들어라 — 직접 산출한 지표, 자체 집계,
      현장에서 관측한 값
- [ ] 그 숫자에 이름을 붙이고 **항상 같은 URL**에서 서빙하라 (안정 URL = 인용 주소)
- [ ] **문단 단위 인용 가능성**: 각 문단이 [주어 + 수치 + 기준일 + 산출 방식]을 갖추면
      그 문단째로 인용된다. 엔진들은 페이지가 아니라 문단을 잘라 간다

**온드와 외부가 같은 말을 해야 채택된다.** AI는 자사 페이지의 주장을 **외부(커뮤니티·언론·
소셜)에서 사람들이 같은 말로 하고 있을 때** 믿고 가져간다. 온드에만 쌓은 주장은 반쪽이다.
지어내는 바이럴이 아니라 **같은 경험을 하게 해 같은 말이 나오게** 만드는 것이 강화다.
→ 제3자 표면을 어디부터 손대는지는 `reputation.md`.

### 채널 지도 — 어디에 무엇을 올리나

채널을 고르는 순간 도달할 수 있는 엔진의 범위가 정해진다. 그리고 채널마다 **올릴 것이
다르다** — 같은 글을 복붙해 뿌리는 것은 배포가 아니라 중복이다.

| 채널 | 주로 닿는 곳 | 올릴 것 | 형식·주의 |
|---|---|---|---|
| **자사 도메인** | 전 엔진 | 팩트의 원장 — 요금·조건·데이터의 **원본**, 의도 랜딩, FAQ | Phase 3~4 산출물. 문단 단위 인용 구조(주어+수치+기준일). 다른 모든 채널이 여기로 링크 |
| **폐쇄형 블로그**(네이버 등) | 해당 플랫폼 + 일부 엔진 | 원본의 **요약 + 원문 링크**, 후기·소식 등 체류형 글 | 원본을 여기 두면 글로벌 엔진에겐 없는 글이 된다 (`naver.md` 3번) |
| **오픈웹 블로그**(티스토리 등) | ChatGPT·Gemini 계열 | 가이드·비교글의 오픈웹 판, 기술·과정 기록 | 자사 원본과 **같은 수치·같은 기준일**로. 어긋나면 역효과 |
| **채용·비즈니스 프로필** | 전 엔진 (게시판형이라 잘 읽힘) | Phase 2에서 확정한 **공식 소개문 그대로** + 갱신일 | 방치가 최악 — 낡은 프로필이 회사를 설명한다 (`reputation.md` 4번) |
| **유튜브** | 구글 계열(AI Overviews·Gemini)에서 인용 관측이 잦다 | 설명·비교 영상 + **설명란에 핵심 수치와 원문 링크** | 영상 속 말은 색인이 불완전하다 — 텍스트(제목·설명란·자막)에 담아야 잡힌다 |
| **커뮤니티·후기** | 검토 단계 질문 흡수 | 직접 게시하는 곳이 아니다 — **같은 경험이 같은 말로 나오게** 만드는 곳 | 위장 게시·품앗이는 감지되면 채널 전체 신뢰가 깎인다 |
| **언론·보도** | 엔진별 편차, B2B는 전문지가 앞서기도 | 근거 있는 발표(수치+기준일), 인터뷰 | 보도자료에 공식 메시지를 **같은 문구로** — 기사 제목·문장이 AI 답변에 반복된다 |
| **위키류** | 인용 비중 높음 | 직접 편집 대상 아님 | 사실관계·최신성 **모니터링만** (`reputation.md` 3번) |

순서는 언제나 같다: **원장(자사)이 먼저, 배급(채널)은 그다음.** 원본 없이 채널부터 하면
링크할 곳이 없고, 채널끼리 수치가 어긋나는 순간 전부를 잃는다.

## 4. 엔진별 — ChatGPT

- [ ] **Bing Webmaster Tools 등록**을 검색 발견·진단 채널로 활용한다. ChatGPT의 출처 선택은
      변할 수 있으므로 Bing 등록만으로 노출 또는 인용을 보장한다고 보지 않는다
- [ ] IndexNow 연동 (Bing이 직접 소비한다) — 신규 페이지 반영 가속
- [ ] `site:도메인`을 **Bing에서** 실제로 쳐 색인 확인
- [ ] robots: `GPTBot`, `OAI-SearchBot`, `ChatGPT-User` 3종 허용

## 5. 엔진별 — Gemini ★ 구조가 다르다

Gemini의 검색 기반 답변은 Google 검색·그라운딩 인프라를 활용할 수 있다. 제품과 모드에 따라
동작이 달라질 수 있으므로 실제 출처를 함께 관측한다.

- [ ] **GSC 색인 상태를 먼저 확인하라.** Google 검색 기반 표면에서는 중요한 선행 조건이다.
      `seo.md`의 SSR·사이트맵부터 하라
- [ ] `Google-Extended`는 Gemini 학습과 일부 grounding 사용을 제어하는 별도 토큰이다.
      Google Search 포함·순위의 필수 조건이 아니며, 차단 효과는 제품별 공식 범위를 따른다
- [ ] AI Overviews와 Gemini는 별개 표면이다. AI Overviews는 `aeo.md` 소관
- [ ] ⚠️ **측정 방식이 다르다** — 로그에 안 잡히므로 직접 질의로만 확인 → `measure.md`

## 6. 엔진별 — Claude

- [ ] robots: `ClaudeBot`(학습) / `Claude-SearchBot`(색인) / `Claude-User`(실시간) 3종 허용.
      **학습만 막고 검색·fetch는 열어두는 선택**이 가능하다 (셋이 독립)
- [ ] 로그에서 `Claude-SearchBot` 방문 확인 — 색인 진입의 선행지표
- [ ] Claude는 실시간 fetch 비중이 있으므로 **SSR 응답 속도**가 인용에 영향

## 7. 검증

각 엔진에 **실제로 질문을 던져** 출처 목록에 도메인이 뜨는지 확인한다.
안 뜨면 순서대로 점검:

1. 크롤러 허용됐나 (robots.txt)
2. 원시 HTML과 필요한 렌더링 결과가 접근 가능한가
3. 관련 검색 색인과 실제 답변 출처에서 관측되는가
4. 경쟁 원출처가 이미 있나 (있으면 1차 소스 차별화 필요)

여기까지가 기술 점검이다. 자사 사실·질문 조건·제3자 채널까지 이어지는 전체 순서와
자료를 더할 위치는 [미노출 진단](../ops/gap.md)을 따른다.
