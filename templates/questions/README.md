# 공식 상품 자료에서 고객 질문지 만들기

[실행 명령 4개](../../README.ko.md#공식-상품-자료로-고객-질문지-만들기-api-키-불필요)는 모두 로컬 파일만 읽는다. 이 폴더의 회사, 검색어, 응답과 페이지는 **가상 예제**다.

1. **근거를 준비한다.** [catalog.json](catalog.json)을 복사하고 공식 상품 페이지·카탈로그·약관에서 확인한 원문을 [official.txt](official.txt)처럼 함께 저장한다. 상품 ID는 앞으로도 그대로 쓸 값을 고른다. 공식 URL(사이트와 같은 호스트), 확인일, 실제 판매 상태, 상품·강점·적용 범위와 예외의 원문을 입력한다. 담당자가 공식 문서의 진위와 해석을 검토한 뒤에만 `verified: true`로 표시한다. 도구는 저장한 텍스트와 인용문의 일치를 검사한다. 현재 판매 여부를 웹에서 자동 인증하지는 않는다.
2. **고객의 상황을 적는다.** `relevance`는 사업 기준으로 `core` 또는 `supporting`이다. 다음에는 브랜드를 모르는 사람이 말할 법한 상황(`situation`), 필요한 일반 상품·조건(`need`), 계약 전 확인할 점(`check`)을 적는다. 이때 원문이 보장하지 않는 혜택은 넣지 않는다. `brand_names`에 회사명·상품 고유명·별칭을 넣는다. `locale`은 ko 또는 en이다. 확인 가능한 검색어·CS 질문은 익명화한 표현과 참조 번호를 `wording`에 넣는다. 동일 의도·유형의 가설보다 그 표현을 우선한다.
3. **후보를 검토한다.** `review.json`에서 탐색(find)·비교(compare)·조건(check), 브랜드 유형, 근거와 보류 사유를 확인한다. 실제 표현이 없으면 `product_hypothesis`다. 검색량으로 해석하지 않는다. 선택 사항인 `--log`에는 해당 사이트와 비교할 캠페인의 측정 로그만 전달한다. 핵심 상품이면 한 단계, 같은 ID·문구·유형의 비로그인 검색 활성 세션에서 공식 인용 누락이 확인되면 한 단계 우선한다(P3 → P2 → P1). `known_runs: 0`은 미확인이다. 특정 회차의 인용 누락이 전체 채널의 노출 실패라는 뜻은 아니다.
4. **채택한 질문만 내보낸다.** `selection-template.json`을 복사해 미채택 행을 삭제하고 각 행에 선정 사유(`reason`)를 쓴다. [selected.json](selected.json)은 예제 자료와 예제 로그에만 맞는 검토 결과다. 문구·근거·우선순위를 바꾸면 다시 후보를 만들고 검토한다. 두 번째 명령의 결과는 측정용 `queries.json`과 선정 사유·근거가 포함된 `brief.json`이다. 기존 측정 세트가 있으면 `--existing 기존/measure/queries.json`을 함께 준다. 새 폴더에 기존 행을 보존한 사본이 생성되고 ID·문구 충돌은 거절된다. 원본 세트와 응답 로그는 수정하지 않는다. brief는 이번에 채택한 질문만 담는다. 측정에는 질문 원문만 쓴다.
5. **경쟁사와 비교하고 같은 질문으로 재측정한다.** 예제에서 `drill-day.find.nonbrand`는 원문의 ‘토요일 하루 대여’를 확인하고 채택한 질문이다. [가상 응답](answer.txt)에는 주말공방 언급과 공식 홈페이지 일반 링크가 있지만, [로그](baseline.jsonl)의 출처 패널에는 다른 대여점의 `example.org/weekend-drill/`만 있다. 따라서 브랜드 언급은 예, 공식 인용은 아니오다. 세 번째 명령의 `plan.json`에서 이 페이지는 `observed_publisher`로 연결된다. [페이지 자료](research.json)상 이곳에는 ‘토요일 반납 시각’ 표제가 있고 공식 `example.com/service/`에는 없다. 이는 공식 페이지에 지점별 반납 시각을 보강할 근거이지 AI의 선택 이유가 증명된 것은 아니다. 네 번째 명령은 브랜드 지명 질문을 제외한 동일 ID·원문의 재측정 슬롯을 만든다. 개선 후 같은 채널·조건에서 직접 관측할 때까지 슬롯은 `pending`이다.

실제 운영에서는 [측정 안내](../../ops/measure.md)에 따라 고정 세트를 사용한다. 재현성을 위해 새 실행에는 새 출력 디렉터리를 지정한다. 재구축 자동 실행에는 내보낸 brief 경로를 설정의 `brief_file`로 전달할 수 있다.
