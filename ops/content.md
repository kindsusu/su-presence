# 콘텐츠 운영 — 질문에서 갱신까지

이 문서는 실제 질문을 찾아 기존 페이지에 답을 보강하거나 필요한 페이지만 발행하는 작업표다.
검색 노출과 AI 인용은 발행 자체로 보장되지 않는다. 질문 선택은 [의도 발굴](intent.md),
본문 표현은 [AEO](../lanes/aeo.md), 접근성은 [SEO](../lanes/seo.md), 성과 판정은
[측정 운영](measure.md)을 함께 따른다.

## 1. 페이지와 질문의 현재 상태를 적는다

[인벤토리 CSV](../templates/content-inventory.example.csv)를 복사해 자사 페이지를 한 행씩 적는다.
URL, 해당 질문의 `query_id`(고정 측정 질의에 포함된 경우), 발행일·실제 내용 수정일,
상태와 다음 검토 예정일을 기록한다. 검색 성과는 출처와 집계 시작·종료일을 붙여 노출·클릭을
적는다. 검색 콘솔 접근이 없거나 해당 기간에 측정하지 않았다면 숫자를 **빈칸**으로 둔다.
빈칸은 0이 아니다. `next_due`는 검토할 날짜 메모이며 예약 작업이 아니다.
상태는 팀에서 쓰는 값(예: `draft`, `published`, `refresh`, `merge`, `retired`)을 일관되게
적고, 병합한 행은 `destination_url`에 정본 URL을 넣는다.

측정 질의의 원본은 `out/<host>/measure/queries.json`, 인용 관측의 원본은
`out/<host>/measure/log.jsonl`과 보고서다. CSV의 `query_id`와 `evidence_ref`는 이 기록을
가리키며 인용률을 다시 입력하지 않는다. 실제 사이트 데이터와 고객 문의는 저장소에 올리지 않는다.

## 2. 근거가 있는 질문 백로그를 만든다

GSC·서치어드바이저 검색어, 실제 문의, 자동완성, 경쟁 인용 페이지에서 질문을 모은다.
각 후보에 **질문 원문, 발견 날짜, 출처 링크 또는 내부 기록 위치, 대상 독자,
기존 답변 URL, 결정**을 적는다. 고객 정보를 포함한 문의는 비식별화한다. 추정 검색량과
직감만으로 수요를 확정하지 않는다. 한 답으로 처리할 수 있는 표현 변형은 묶고, 답·대상·
근거가 다를 때만 별도 페이지를 검토한다. 기존 URL에 답을 더할 수 있는지 먼저 판단한다.
측정 대상으로 채택한 질문은 기존 ID를 바꾸지 않고 `queries.json`에 새 ID로 추가한다.

## 3. 근거를 확보한 뒤 브리프를 쓴다

[콘텐츠 브리프](../templates/content-brief.example.md)에 질문, 한 문장 답, 적용 조건·예외,
각 주장의 근거와 기준일, 원출처 링크, 관련 내부 페이지를 채운다. 확인되지 않은 수치나
비교 우위는 쓰지 않는다. 게시 주체가 직접 아는 사실과 외부 자료를 구분한다. 답이 기존
페이지와 같다면 신규 발행 대신 그 페이지의 갱신 또는 병합을 제안한다.

## 4. 조건에 맞는 게시 점검만 한다

- 질문에 대한 답이 본문 앞쪽에 있고, 조건·단위·기준일을 떼어 읽어도 오해가 없는지
  [AEO 점검](../lanes/aeo.md)을 따른다. 실제 질문이 있을 때만 FAQ를 쓰며 FAQPage 구조화
  데이터는 보이는 내용과 일치할 때만 추가한다.
- 공개 웹 페이지라면 [SEO 점검](../lanes/seo.md)에 따라 접근·색인 차단·canonical·사이트맵과
  모바일 표시를 확인한다. `llms.txt`를 발행 조건으로 삼지 않는다.
- 배포 파일을 실제 서빙하는 경우 [배포 검증](../tools/README.md#verifypy--배포-후-검증)을
  실행한다. 배포 후 검색 노출·인용은 [측정 운영](measure.md)에 따라 별도로 관찰한다.
- 외부 채널에도 올린다면 대상 채널의 **편집기에서 Markdown 렌더링**(제목·표·링크·이미지)을
  확인하고 모바일 미리보기를 본다. 요약·링크·출처 표기는 채널 정책에 맞춘다.

## 5. 갱신·병합 결과를 남긴다

기준이 바뀌면 같은 URL의 답과 근거를 고치고, 실제 내용 수정일을 기록한다. 단순 날짜
교체를 갱신으로 쓰지 않는다. 두 페이지가 같은 답을 반복하면 정본 URL을 정하고 병합
대상·이전 URL·이동 또는 canonical 처리·링크 수정·검증 결과를 브리프와 인벤토리에 남긴다.
그 뒤 같은 기간·조건의 검색 지표와 고정 질의 관측을 비교한다. 색인이나 인용에 걸리는
기간을 보장하지 않으며, 미측정·오류를 성과 0으로 바꾸지 않는다.
