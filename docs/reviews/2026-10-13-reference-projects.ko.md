## su-presence에 옮길 설계 원칙

1. **노출된 사이트의 관측과 경쟁사 벤치마크를 분리한다.** 대상 사이트의 홈페이지·사이트맵·주요 서비스/상품·가격·소개·문의 페이지를 우선 수집하고, 사이트맵이 없으면 내부 링크로 발견한다. 원시 HTML과 렌더 결과, HTTP 상태, canonical, 색인 차단, 제목·본문·구조화 데이터, 마지막 확인 시각을 URL별로 보관한다. `geo-audit`의 50쪽/30초 제한은 안전한 표본 수집 아이디어이지 전체 사이트 분석을 보장하는 수치가 아니다. 경쟁사 페이지는 같은 항목으로 측정하고, 접근 실패와 공개되지 않은 가격·기능은 **미확인**으로 남긴다. 근거: [geo-audit](https://github.com/zubair-trabzada/geo-seo-claude/blob/989cae01e8ebbc42a9ec798eb9e7cb423f5ec89c/skills/geo-audit/SKILL.md), [competitor-pages](https://github.com/AgriciDaniel/claude-seo/blob/4b99de2f7de7e7d5247042e5fb5b4ea9368ef734/skills/seo-competitor-pages/SKILL.md).
2. **실제 페이지 청사진은 현재 페이지와 근거가 있는 빈틈에서 만든다.** 페이지별 기록은 `의도/질문 → 현재 URL 또는 신규 필요 → 경쟁사 출처 URL → 기존 강점·부족한 절 → H1·직답·절 구성 → 증거·기준일 → 내부 링크 → CTA → 검증 조건` 순서로 둔다. 기존 URL이면 유지·보강할 절을 표시하고, 허브라면 대상 사이트에 실제 있는 모든 하위 서비스/상품을 포함한다. 서비스·블로그·비교·사례·홈 등은 서로 다른 구성으로 작성한다. 경쟁사에만 있는 제공 기능을 자사 페이지에 쓰지 않는다. 근거: [content-brief](https://github.com/AgriciDaniel/claude-seo/blob/4b99de2f7de7e7d5247042e5fb5b4ea9368ef734/skills/seo-content-brief/SKILL.md), [page-type-templates](https://github.com/AgriciDaniel/claude-seo/blob/4b99de2f7de7e7d5247042e5fb5b4ea9368ef734/skills/seo-content-brief/references/page-type-templates.md), [competitor-pages](https://github.com/AgriciDaniel/claude-seo/blob/4b99de2f7de7e7d5247042e5fb5b4ea9368ef734/skills/seo-competitor-pages/SKILL.md).
3. **원본 페이지와 채널별 요약을 연결한다.** 자사 도메인에 출처·기준일·수정일이 있는 답변/데이터/비교 페이지를 원본으로 두고, 네이버 블로그·브런치·Medium 등에는 채널에 맞는 요약과 원본 링크를 배포한다. 비교 페이지에는 자사 소속, 평가 기준, 경쟁사 강점, 각 주장 출처와 가격 확인일을 밝힌다. 외부 플랫폼에서 원본 전문 중복 발행·canonical 가능 여부는 채널별로 확인한다. 이 운영 구조는 [content](https://github.com/leopard627/fire-your-seo-agency/blob/5f7249f7eff119703f2a509d0dc5e21b7b3ccc4c/references/content.md) 2·7절, [neo-naver](https://github.com/leopard627/fire-your-seo-agency/blob/5f7249f7eff119703f2a509d0dc5e21b7b3ccc4c/references/neo-naver.md) 3절에 있다. 네이버 내부 노출 우대나 AI 브리핑 인용 메커니즘은 이 문서의 주장일 뿐, 이 조사에서 독립 검증하지 않았다.
4. **발행과 성과를 별도 검증한다.** 발행 전 원시 HTML에 직답·표·링크가 보이는지, title/description·canonical·사이트맵·구조화 데이터와 화면 내용이 일치하는지 확인한다. 발행 뒤에는 GSC·네이버 검색 데이터의 노출/클릭, 목표 질문의 실제 인용, 채널별 유입을 기준선과 같은 기간으로 재측정한다. 발행량이나 내부 GEO 점수 상승을 검색·AI 인용 성과로 표기하지 않는다. 출처: [content](https://github.com/leopard627/fire-your-seo-agency/blob/5f7249f7eff119703f2a509d0dc5e21b7b3ccc4c/references/content.md) 4·8절, [measure](https://github.com/leopard627/fire-your-seo-agency/blob/5f7249f7eff119703f2a509d0dc5e21b7b3ccc4c/references/measure.md).

## 그대로 약속하지 않을 항목

- `geo-seo-claude`의 GEO 점수는 자체 가중치·문장 길이·`llms.txt` 존재에 점수를 주는 **내부 휴리스틱**이다([scoring-methodology](https://github.com/zubair-trabzada/geo-seo-claude/blob/989cae01e8ebbc42a9ec798eb9e7cb423f5ec89c/docs/scoring-methodology.md)). AI 검색 인용 확률이나 플랫폼별 순위를 뜻하지 않는다. `claude-seo`의 [llmstxt-evidence](https://github.com/AgriciDaniel/claude-seo/blob/4b99de2f7de7e7d5247042e5fb5b4ea9368ef734/skills/seo-geo/references/llmstxt-evidence.md)는 `llms.txt`에 검색 인용 가중치를 두지 말라고 명시한다. 따라서 선택적 파일 검사로만 취급한다.
- `fire-your-seo-agency`의 “질문 하나 = 페이지 하나”, 14일 재측정, 발행 후 1~3일 외부 배포, FAQPage/IndexNow 관련 체크리스트는 운영 가설·일정이다. 모든 질문에 새 URL을 만들거나, 정해진 일수에 색인·인용을 보장하지 않는다. 중복 질문은 기존 페이지 보강·병합을 먼저 검토한다. 근거: [content](https://github.com/leopard627/fire-your-seo-agency/blob/5f7249f7eff119703f2a509d0dc5e21b7b3ccc4c/references/content.md).
- 비교 스킬의 “high-converting”, 브리프 스킬의 “outranking”, 월간 보고의 점수 개선을 고객 성과 약속으로 번역하지 않는다. 모든 비교 주장과 검색 결과 관측은 날짜·URL·관측 방법을 남겨 재검증 가능하게 한다.

**저작권 적용:** 세 저장소 모두 MIT이므로 아이디어를 자체 설계로 구현할 수 있다. 코드·템플릿의 실질적 부분을 복사하면 해당 MIT 저작권 고지와 허가문을 포함해야 한다. 이 문서는 코드를 복사하지 않았으며 참조 설계만 요약했다.
