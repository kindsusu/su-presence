# 측정 루프 — 수정은 절반, 확인이 나머지 절반

대행 보고서와 이 플레이북의 차이는 여기다. **측정 없는 최적화는 주장일 뿐이다.**

## 1. 기준선 — 손대기 전에 먼저 남긴다

변경 전 상태를 기록하지 않으면 효과를 영원히 증명할 수 없다.

처음 실행하거나 산출물이 의심되면 통합 진입점으로 환경과 로컬 상태부터 확인한다.

```bash
python tools/seo_geo.py doctor
python tools/seo_geo.py audit example.com --out out --max-pages 300 --lang ko
python tools/seo_geo.py status out/example.com/audit.json
```

`doctor`는 Python 3.10+와 도구 import만 확인하며 네트워크를 조회하지 않는다. `audit`는 크롤과
HTML 보고서를 함께 만들고, 크롤 범위가 불완전하면 파일은 보존하되 exit code 2를 낸다.
`status` 역시 로컬 산출물 기록만 보여 준다. 배포 상태나 검색 성과를 새로 확인하지 않으며,
표시된 `next_due`가 실제 예약됐다는 뜻도 아니다.

배포 초안을 만들 때 `generate.py`는 `.su-multi-geo-generated.json` manifest에 자신이 만든
파일만 기록한다. 다음 생성에서 같은 범주의 낡은 산출물을 정리하므로 사용자 파일과 생성 파일을
구분할 수 있다. `audit.json`의 `coverage.complete`가 true가 아니거나 기존 사이트맵 URL의
누락 위험이 있으면 교체용 sitemap XML을 만들지 않고 `DEPLOY.md`에 **교체 금지**로 남긴다.
이때 기존 사이트맵을 덮어쓰지 말고 크롤 한도·실패 원인을 해결한 뒤 다시 `audit`와 `generate`를 실행한다.

| 항목 | 어디서 | 주기 |
|---|---|---|
| 노출·클릭·평균순위 | Google Search Console (28일) | 주 1회 |
| Bing 노출·클릭 | Bing Webmaster Tools | 주 1회 |
| 네이버 노출·클릭·검색어 | 서치어드바이저 | 주 1회 |
| 색인 수 | GSC + `site:도메인` (구글·빙 각각) | 주 1회 |
| **AI 인용 O/X** | 아래 2번 프로토콜 | 2주 1회 |
| **AI 크롤러 방문** | 서버 접근 로그 | 주 1회 |
| **AI 리퍼러 유입** | GA4 트래픽 획득 → 세션 소스 필터 | 주 1회 |

`chatgpt.com`·`perplexity.ai`·`gemini.google.com`·`claude.ai`·`copilot.microsoft.com`을
세션 소스로 필터링한다. 이것이 **인용 O/X 수동 확인과 달리 자동으로 쌓이는 유일한 인용
후행지표**다 — 인용이 실제 방문으로 이어졌다는 유일한 자동 증거이기도 하다.
⚠️ 다만 **구조적으로 과소집계된다.** 리퍼러를 넘기지 않는 클라이언트(앱 내 브라우저,
일부 리다이렉트 경유)는 다이렉트로 잡히므로, 절대값이 아니라 **추이**로만 읽어라.

```bash
# AI 크롤러 방문 집계 — 인용보다 먼저 움직이는 선행지표
grep -icE 'GPTBot|OAI-SearchBot|ChatGPT-User|ClaudeBot|Claude-SearchBot|Claude-User|PerplexityBot|Perplexity-User' access.log

# 벤더별로 쪼개서 추이를 본다
for ua in GPTBot OAI-SearchBot ChatGPT-User ClaudeBot Claude-SearchBot Claude-User PerplexityBot; do
  printf '%-20s %s\n' "$ua" "$(grep -icF "$ua" access.log)"
done
```
로그 접근이 없으면 Cloudflare·Vercel 등 호스팅 대시보드의 봇 트래픽 분류로 대체한다.

## 2. AI 인용 측정 프로토콜 — 엔진마다 방법이 다르다

대상 질문 **5~10개를 고정**해두고 매번 같은 질문으로 잰다. 질문이 바뀌면 추이가 무의미하다.
5~10개는 시작 기준이다 — 본격 운영에 들어가면 브랜드+비브랜드 합쳐 **40~50개 수준**까지 늘린다.

| 엔진 | 로그 관측 | 측정 방법 |
|---|---|---|
| ChatGPT | ✅ UA 3종 | 검색 모드로 질의 → 출처 목록에 도메인 O/X |
| **Gemini** | ❌ **불가** | **직접 질의만이 유일한 방법** |
| Claude | ✅ UA 3종 | 웹 검색 켜고 질의 → 인용 O/X |
| Perplexity | ✅ UA 2종 | 질의 → 출처 카드 O/X |
| 네이버 AI 브리핑 | ❌ | 네이버 앱에서 검색 → 출처 칩 O/X |
| Google AI Overviews | ❌ | 구글 검색 → 답변 박스 출처 O/X |

> **⚠️ Gemini는 선행지표가 없다.**
> `Google-Extended`는 user-agent가 아니라 robots.txt 토큰이라 서버 로그에 **절대 나타나지
> 않는다.** 다른 엔진처럼 "크롤러가 왔으니 곧 인용되겠다"를 볼 수 없다.
> 대신 **GSC 색인 수**를 Gemini의 선행지표로 삼아라 — Googlebot 색인이 Gemini 도달의
> 유일한 관문이다. 색인이 늘면 Gemini 도달 가능성이 늘어난 것이다.

### 엔진 우선순위 — 전부 못 재면 어디부터

**ChatGPT와 구글 AI Overviews부터 잰다.** 구글은 로그인도 구독도 없이 기본으로 노출되는
표면이라 실사용 비중이 가장 크고, 여기서 뜨면 AI 모드·Gemini로 이어진다. Claude·Copilot은
사용 비중이 상대적으로 작다 — **후순위**로 붙인다. 엔진 수를 늘리는 것보다 두 엔진을
**같은 조건으로 계속 재는 것**이 먼저다.

### 측정 조건 — 이 셋을 어기면 숫자가 오염된다

- [ ] **비로그인·시크릿 창으로 질의한다.** 로그인 상태면 대화 이력·계정 설정이 반영된
      개인화 답이 나온다. 우리가 재려는 건 "그 사람에게 뜬 답"이 아니라 "누구에게나 뜨는 답"이다
- [ ] **같은 질문을 같은 날 5~10회(여력이 되면 10회) 반복**하고 공통으로 나오는 출처를 본다.
      생성 답변은 매번 다르다 — ⚠️ **1회 질의 결과는 표본이 아니다.** "떴다/안 떴다"가 아니라
      **10회 중 몇 회**로 적어라.
      ⚠️ 반복은 **같은 날에 몰아서** 해야 답변의 분포를 본다. 며칠에 나눠 재면 분포가 아니라
      그 사이의 색인·소스 변화가 섞여 들어온다
- [ ] **인용된 URL을 남긴다.** O/X만 적으면 다음에 할 일이 정해지지 않는다.
      빈도(얼마나 자주)와 URL(어느 페이지가)이 같이 있어야 "그 페이지를 강화"인지
      "그 질문용 페이지가 없음"인지 갈린다

### 반복 측정 자체가 오염원이 된다 — 간격과 응답 검증

"같은 날 10회 반복"은 맞는 원칙이지만, **몰아치면 검색엔진이 축소 응답을 준다.**
그 응답으로 집계하면 `0`이 찍히는데 그건 엔진의 사실이 아니라 **우리가 만든 0**이다.

> 실제 사고: 브랜드 질의를 10회 연속으로 돌려 `자연노출 0/10`을 얻었다.
> 같은 질의를 같은 날 단발로 재면 노출이 있었고 화면 캡처까지 있었다.
> 응답 크기를 보니 **24KB — 정상 SERP는 1.1MB**였다. 스로틀링이었다.

- [ ] 요청 간격을 **3초 이상** 둔다 (`tools/measure_kr.py --pause`)
- [ ] **응답 건전성 게이트를 통과한 응답만 집계한다.** 정상 SERP는 수백 KB다.
      바닥을 못 넘으면 **0으로 기록하지 말고 측정 실패로 남긴다** — 도구가 이걸 강제한다
- [ ] 스로틀에 걸렸으면 시간을 두고 다시 잰다. 같은 날 못 채우면 **횟수를 줄여 적되
      몇 회인지 밝힌다**(`3/3` 처럼). 채우지 못한 것을 채운 것처럼 적지 않는다

### 엔진별 중립 모드 — "시크릿 창"만으로는 부족하다

로그인이 필요한 엔진은 각 서비스의 **중립 모드**를 켜야 한다. 브라우저 시크릿 창과 다르다.

| 엔진 | 중립 모드 | 남는 오염 |
|---|---|---|
| ChatGPT | **임시 채팅** (헤더에 "맞춤화 안 함") | — |
| Gemini | **임시 채팅** (점선 원 안 연필 아이콘) | — |
| Claude | **시크릿 모드** (유령 아이콘, `?incognito=`) | ⚠️ **계정 프로필은 계속 적용된다** |
| Perplexity | 비로그인 | — |

⚠️ **프로필·메모리에서 유래한 응답은 집계에서 뺀다.** 시크릿 모드는 저장·학습만 막고
계정 프로필 설정은 살려두는 경우가 있다. 모델이 회사명을 말했더라도 그게 **질문자가 이미
제공한 정보**에서 나온 것이면 웹 인용이 아니다. 인용으로 세면 수치가 부풀려진다.
그런 응답은 **미노출로 처리**하고, 개인정보에 해당하면 기록·캡처에도 남기지 않는다.

### 측정 범위를 수치에 붙여 적는다

전수로 재지 않은 것을 전수처럼 적지 마라. 검색엔진은 질의를 기계로 돌릴 수 있어 전수가 쉽지만,
대화형 엔진은 브라우저를 사람이 몰아야 해서 대개 대표 질문만 재게 된다. **그 차이를 표기에 남긴다.**

| 표기 | 뜻 |
|---|---|
| `0 / 7` | 비브랜드 7개 **전수** 측정 |
| `0건 (대표질문)` | 대표 질문만 측정 |
| `미측정` | 질의하지 않음 |

> 실제 사고: 대표 질문 1개만 재고 `0/7`로 적어 보고 직전까지 갔다. 숫자는 맞았지만
> **"몇 개 물어봤나"에 답할 수 없는 표기**였다.

### 0건이 나오면 도구를 바꿔 한 번 더 확인한다

**0은 가장 극적인 숫자라 가장 검증이 필요하다.** 그리고 0은 도구 탓일 때가 있다.

> 실제 사고: 샌드박스 브라우저로 다음 브랜드 질의를 재서 "웹 결과 0건"으로 보고했는데,
> 같은 URL을 일반 Chrome으로 열자 자사 사이트가 있었다. **엔진이 아니라 도구가 만든 0** 이었다.
> 다음날 같은 샌드박스로 다시 재도 여전히 0이 나왔다 — 재현된다고 사실인 것은 아니다.

- [ ] 0건은 **UA·브라우저를 바꿔** 재확인한다 (헤드리스 ↔ 실제 브라우저, 기본 UA ↔ 브라우저 UA)
- [ ] HTML 원문 grep으로 판정하지 않는다. `<script>` 안의 JSON 페이로드에 남의 페이지가
      우리 도메인을 참조해 두면 오탐이 난다 — **렌더링된 가시 텍스트**로 판정한다

### 브랜드 질의와 비브랜드 질의는 다른 지표다

두 세트를 **따로 고정하고 따로 추이를 본다.** 섞어서 평균 내면 둘 다 안 보인다.

| 세트 | 예 | 읽는 법 |
|---|---|---|
| **브랜드 질의** | "○○ 렌터카 요금", "○○ 어떤 회사야" | 대개 뜬다. 안 뜨면 사고 신호(색인·크롤러·엔티티 분열) |
| **비브랜드 질의** | "장기렌트 요금 비교", "법인 차량 리스 조건" | **진짜 승부처.** 여기서 뜨면 우리를 모르던 수요에 닿은 것 |

브랜드 질의만 오르는 상태는 개선이 아니라 **원래 알던 사람에게만 보이는 상태**다.

기록 형식 — **빈도와 URL을 같은 줄에 남긴다**:
```
2026-09-15 | 비브랜드 Q3 "장기렌트 요금 비교" | 비로그인 · 같은 날 10회
  ChatGPT   3/10  https://example.com/long-term-rate
  Gemini    0/10  —
  Claude    7/10  https://example.com/long-term-rate (5) / /faq-rate (2)
  네이버AI   0/10  —
```
URL 열이 비어 있으면 만들 페이지가 없다는 뜻이고, 같은 URL이 반복되면 그 페이지가
우리 인용 자산이라는 뜻이다. 다음 작업은 이 열을 보고 정한다.

### 도구 — `tools/measure.py`, 엔진별 접근법은 `ops/measure-playbook.md`

이 프로토콜을 손으로 굴리지 마라. 기록 형식이 사람마다 달라지면 추이가 깨진다.

```bash
python tools/measure.py init   out/<host>/audit.json   # 질의 세트 빈칸 만들기 → 사람이 채운다
python tools/measure.py form   out/<host>/audit.json --engines chatgpt,gemini,claude,perplexity --runs 5
#   → measure/form-<날짜>.csv (엑셀) + measure/form-<날짜>.html (오프라인 입력 폼)
#   ── 여기서 사람이 비로그인·시크릿 창으로 실제 측정한다 ──
python tools/measure.py import out/<host>/audit.json measure/form-<날짜>-filled.csv
python tools/measure.py report out/<host>/audit.json   # 최신 측정일 → summary.json + MEASURE.md
# 기간 전체 누적이 필요할 때만 명시한다
python tools/measure.py report out/<host>/audit.json --since 2026-09-01 --until 2026-09-30 --cumulative
```

- **수동 입력이 기본 골격이다.** API 키가 하나도 없어도 측정 루프는 완전히 돈다.
  폼 상단에 위 측정 조건이 체크리스트로 박혀 있다
- **질의는 도구가 지어내지 않는다.** `init`은 빈칸과 힌트만 준다 — 문장은 사람이 적는다.
  한 번 고정하면 바꾸지 않는다
- `report`의 기본 숫자는 선택 기간에서 **가장 최신 측정일 한 회차**다. 날짜별 `trend`는
  그대로 보존된다. 여러 날짜를 합친 값이 필요할 때만 `--cumulative`를 쓴다
- `python tools/measure.py auto ...`는 **선택 플러그인**이다. `OPENAI_API_KEY`·
  `ANTHROPIC_API_KEY`가 환경변수에 있을 때만 ChatGPT·Claude를 자동으로 돌린다.
  키가 없으면 "수동 모드"를 안내하고 그냥 끝난다(에러 아님).
  자동이든 수동이든 같은 `log.jsonl`에 쌓이지만 `mode`·`surface`·모델·locale·로그인·검색
  조건이 다른 **별도 cohort**로 집계된다. ChatGPT 웹 UI와 OpenAI API 모델 결과를 합쳐
  하나의 ChatGPT 성과로 해석하지 않는다
- ⚠️ **API 응답은 비로그인 웹 UI와 다른 표면이다.** 자동 측정은 수동 측정을 대체하지 않는다 —
  추세를 싸게 자주 보는 보조 수단이다. Gemini·Perplexity·Google AI Overviews·네이버·
  다음·Copilot은 자동화 대상이 아니다(수동 폼으로만 잰다)
- 비용은 전부 사용자 부담이다. `auto`는 실행 전에 예상 호출 수를 세어 확인을 받는다
- API 오류는 `outcome=error`로 기록하며 **미인용으로 세지 않고 인용률 분모에서도 뺀다.**
  오류율은 별도로 보고하고, 오류가 있는 회차는 회귀 확정에 쓰지 않는다. 응답 원문은 저장하지 않는다

## 3. 재측정 일정 — 작업의 일부다

- 검색 반영에는 시차가 있다. **변경 후 14일 뒤 재측정**이 기본
- 집계 지연 때문에 **최근 2~3일은 빼고** 비교하라
- LLMO는 학습 주기 단위라 **분기 1회**로 따로 잰다 (`llmo.md`)
- 재측정을 기억에 맡기지 마라. **보고에 재측정 날짜를 명시하는 것이 완료 조건이다**

### 도구 — `tools/drift.py`가 그 날짜를 파일로 들고 있는다

```bash
python tools/drift.py snapshot out/<host>/audit.json --label "기준선"
#   → out/<host>/history/audit-<날짜>.json + index.json (sha256·baseline_date·next_due)
python tools/drift.py snapshot out/<host>/audit.json --measure out/<host>/measure/summary.json
python tools/drift.py compare  out/<host>/audit.json   # 기준선 vs 최신 → drift.json + DRIFT.md
python tools/drift.py status   out/<host>/audit.json   # 다음 재측정일까지 며칠 남았나
python tools/drift.py timeline out/<host>/audit.json   # 날짜별 추이 표 → TIMELINE.md
```

- **스냅샷은 불변이다.** 같은 날짜 같은 종류를 다시 저장하면 `--force` 없이는 거부한다 —
  기준선을 나중에 조용히 덮어쓰면 추이 전체가 거짓말이 된다
- `next_due`는 측정 스냅샷이 있으면 **마지막 측정일 + 14일**, 없으면 마지막 스냅샷을
  기준으로 계산된다. 이것은 날짜 계산값일 뿐 캘린더·CI 작업을 실제로 예약하지 않는다.
  `schedule.scheduled=false`와 `status`의 “미등록” 표시를 확인하라. `DRIFT.md` 마지막 절이 그날 돌릴
  명령을 순서대로 적어 둔다 (crawl → snapshot → form → import → report → snapshot → compare)
- `compare`는 같은 질의 fingerprint와 surface/mode/locale/login/search 조건의 cohort만 비교한다.
  API 오류·질의 변경·조건 누락이 있으면 `inconclusive`이며 회귀로 확정하지 않는다. 비브랜드
  인용률은 양쪽 각 5회 이상이고 10%p 이상 변할 때 의미 있는 변화로 판정하며 Wilson 95% 구간도 남긴다
- 확정된 회귀가 있으면 exit code 1을 낸다 — CI에 걸 수 있다

## 4. 낡은 데이터 함정

> **낡음은 하한선 검사로 절대 잡히지 않는다.**

"0이 아님"만 확인하는 감시는 며칠 전 값이 계속 내려와도 통과시킨다.
그래서 파이프라인이 감시해야 할 대상은 값 자체가 아니라 **그 값이 찍힌 시각**이다.
"마지막 갱신이 N일을 넘기면 그 지표는 아예 표시하지 않는다"를 기본 동작으로 두면 안전하다.

`drift.py compare`가 이 검사를 대신한다. 비교 대상 기준선이 `--stale-days`(기본 30)보다
오래됐으면 ⚠️ **"기준선이 낡았다"**를 `drift.json`의 `warnings`와 `DRIFT.md` 머리에 박는다.
그 사이 사이트도 엔진도 여러 번 바뀌었으므로, 그 비교는 *무엇이 바뀌었나*는 말해도
*무엇 때문인가*는 말하지 못한다 — 최근 스냅샷을 하나 더 찍고 다시 비교하라.

## 5. 읽는 법

- **노출 먼저, 클릭은 나중.** 구조 개선의 첫 신호는 노출 증가다. CTR은 제목·설명이
  따라가야 움직인다. 노출만 늘고 CTR이 낮으면 다음 작업은 메타다
- **주말 하락은 정상.** 평일성 주제(B2B·금융·법인)는 주말에 노출이 꺼진다.
  그 패턴이 오히려 실수요의 증거다
- **검색어 목록이 로드맵이다.** GSC·서치어드바이저의 검색어 Top은 "사람들이 실제로 치는
  질문"이다. 상위 검색어 중 **전용 랜딩이 없는 질문 = 다음에 만들 페이지**
- **AI 리퍼러는 후행지표다.** 크롤러 방문(선행) → 인용 O/X(현재) → 리퍼러 유입(후행)
  순으로 움직인다. 리퍼러가 0인데 인용이 확인된다면 정상이다 — 인용은 됐지만 클릭이
  안 나오거나 리퍼러가 안 넘어온 것이다. 반대로 리퍼러가 늘면 인용이 늘었다는 증거다
- **증가율을 조심하라.** 기저가 0에 가까우면 어떤 변화든 수만 %가 나온다.
  보고에는 **절대값을 함께** 적어라

## 6. 보고 형식

`measure.py report`가 내는 `MEASURE.md`의 첫 블록이 아래 AI인용 줄과 같은 형식이다.
검색 지표(노출·클릭·색인)는 GSC·서치어드바이저에서 사람이 채워 앞에 붙인다.

```
[기준선] 8/1~8/28  노출 12,400 · 클릭 180 · 색인 340
                   AI인용 브랜드 2/4 · 비브랜드 0/6 (엔진당 각 10회 질의)
[변경]   8/29      의도 랜딩 6종 + llms.txt + robots 3사 허용 + FAQ LD
[결과]   9/12      노출 31,000(+18,600) · 클릭 610 · 색인 890
                   AI인용 브랜드 4/4 · 비브랜드 3/6 (기준선 대비 비브랜드 +3)
                   └ ChatGPT 2, Google AI Overviews 1, Gemini 0
[재측정] 9/26 예정 (마지막 측정 +14일)
```

`브랜드 4/4`는 **질의 4개 중 4개가 한 번이라도 인용됐다**는 뜻이다.
회차 합산 인용률(`ChatGPT 20/30`처럼)은 `MEASURE.md`의 엔진별 표에 따로 있다 —
둘은 다른 숫자다. 보고에는 **둘 다** 싣는다.

## 7. 인용이 틀렸을 때 — 정정 절차

AI가 우리를 인용했는데 내용이 틀린 경우다. **모든 불만족을 오류로 다루지 마라.**
표현 차이에 시간을 쓰는 동안 진짜 사실 오류가 그대로 남는다.

### 오류 3분류 — 먼저 이걸 나눈다

| 유형 | 무엇 | 조치 |
|---|---|---|
| ① **사실 오류** | 수치·날짜·조건·분류가 틀림 | **정정 우선.** 근거를 붙여 즉시 |
| ② **맥락 누락** | 사실은 맞으나 대상·조건·시점·범위가 빠짐 | 원문에 **조건을 명시**해 다시 쓰게 만든다 |
| ③ **표현 차이** | 표현만 다르고 의미는 같음 | **정정 대상 아님.** 넘어가라 |

⚠️ ③을 ①로 착각하는 것이 이 절차의 최대 낭비다. "우리는 이렇게 안 부르는데"는 오류가 아니다.

### 책임 귀속 — 누가 들고 가는 문제인가

**답변에 아예 없는 것**은 콘텐츠·유통의 문제다 — 마케팅·PR이 들고 간다.
**등장하는데 틀린 것**은 기준의 문제다 — 무엇을 공식 사실로 둘지는 경영진·사업 책임자가 정한다.
이 선이 없으면 정정 요청이 부서 사이에서 멈춘다.

### 정정 경로 3갈래

1. **자사 채널 직접 수정** — 원인이 우리 페이지의 낡은 문장·빠진 조건이면 여기서 끝난다.
   가장 빠르고 가장 흔한 원인이다. 먼저 여기부터 본다
2. **외부에 정정 요청** — **원문 게시자에게 먼저**, 안 되면 플랫폼에.
   근거(공식 페이지 URL·기준일)를 붙이지 않은 요청은 대개 반려된다
3. **직접 못 고치면 근거를 강화한다** — 틀린 서술을 지우는 대신, 정확한 서술이 더 많은
   표면에 더 최신으로 존재하게 만든다 (`llmo.md` 2번, `reputation.md` 3번)

⚠️ **생성형 AI 답변 자체는 신고 창구가 있어도 영구 수정이 보장되지 않는다.** 답변은 매번
새로 생성되므로 "고쳤다"는 확인이 성립하지 않는다. 고칠 대상은 답변이 아니라 **답변이
읽는 소스**다.

### 우선순위는 피해 가능성 순

1. **법적·재무·안전** — 잘못된 요금·계약 조건·안전 정보. 즉시
2. **고객 선택·거래에 영향** — 서비스 범위·가능 여부·처리 기간이 틀림
3. **포지셔닝·표현** — 업종 분류, 소개 문구 톤. 묶어서 분기 단위로

같은 오류가 여러 엔진에서 반복되면 개별 답변이 아니라 **공통 소스가 틀린 것**이다.
`measure.md` 2번의 인용 URL 기록이 그 소스를 짚어 준다.
